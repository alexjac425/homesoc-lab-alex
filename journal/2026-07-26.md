## Metasploitable VM (107) build

- Created VM 107 (`metasploitable-alex`) on SV1: 1 core, 1GB RAM, no disk/ISO at creation time — Metasploitable ships as a pre-built VMware disk image, not an installer, so it's an import rather than an install.
- Set up SSH key auth to SV1 this session too: generated my own ed25519 keypair, sent Tyler the public key to add to `root`'s authorized_keys, removed the passphrase after confirming it worked (`ssh-keygen -p`) since we're sharing the root account by agreement, not separate accounts.
- Downloaded Metasploitable2 from SourceForge (had to find the actual correct URL — the commonly cited direct link 404's, real filename is `metasploitable-linux-2.0.0.zip`), unzipped it, found the real disk image at `Metasploitable.vmdk` (the `.vmx`/`.vmsd`/`.nvram` files alongside it are VMware-specific config, not needed for Proxmox).
- Imported the vmdk with `qm importdisk 107 ... local-lvm`, attached it as `scsi0`, set boot order — but the VM dropped into an initramfs emergency shell on first boot (`does not exist. Dropping to a shell!`).
  - Cause: Metasploitable's kernel is from ~2010 and has no virtio-scsi driver built in, so it couldn't see the disk at all during early boot.
  - Fix: moved the disk from `scsi0` to `ide0` (`qm set --delete scsi0`, `qm set --ide0 ...`, `qm set --boot order=ide0`) — IDE is what the original VMware image expected and what this old kernel actually supports natively.
- Configured the static IP (`10.10.20.20/24`) the old way — this image predates NetworkManager, so it's a plain `/etc/network/interfaces` file instead. Rewrote it a few lines at a time via `sudo bash -c 'echo ... >> ...'` rather than one long command, after a multi-line `printf` attempt got bash stuck waiting on an unclosed quote.
